# Stripe primary-source review — 2026-08-23

Reviewed current Stripe documentation and package metadata before implementing PrediBeacon Pro billing infrastructure.

## Sources reviewed

- Stripe subscriptions integration: hosted Checkout is a supported subscription path.
- Stripe Customer Portal: customers can manage billing information, payment methods, invoices and subscription status in the hosted portal; portal sessions are ephemeral and the portal cannot be embedded in an iframe.
- Stripe no-code portal: customers can authenticate to the Stripe portal by email and receive a login link, but this authenticates them to Stripe's portal, not to PrediBeacon itself.
- Stripe Checkout Sessions API: Checkout sessions are created server-side, can use `client_reference_id` for internal reconciliation, and redirect to provider-hosted Checkout.
- Stripe Customer Portal Sessions API: portal sessions require an existing Stripe customer and return a hosted portal URL.
- PyPI Stripe package: stable Stripe Python 15.4.0 was published 2026-07-29 and requires Python >=3.9.

## Decision

**ADOPT** hosted Checkout and hosted Customer Portal rather than handling card data or building billing UI.

**ADAPT** Stripe lifecycle data into explicit PrediBeacon feature entitlements and keep access decisions inside PrediBeacon.

**REJECT** enabling an unauthenticated public checkout/portal endpoint that accepts arbitrary PrediBeacon account or Stripe customer identifiers. PrediBeacon needs an authenticated customer identity boundary first.

**REJECT** inventing price, trial or discount configuration in source code. Those are owner-controlled commercial facts.

**ADOPT** exact dependency pinning for the billing SDK so production does not change behavior because of an unreviewed package release.
